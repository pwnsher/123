3. EXACT FORMULAS (h in seconds; RV = realized_vol_bps, bps per sqrt-minute)
  sigma_h              = RV_300s * sqrt(h / 60)           None unless RV_300s finite and >= 0.01
  perp_momentum_z_h    = causal_perp_ret_h_bps / sigma_perp_h
  spot_momentum_z_h    = causal_spot_ret_h_bps / sigma_spot_h
  momentum_gap_z_h     = momentum_gap_h_bps / sqrt(sigma_perp_h^2 + sigma_spot_h^2)
  perp_spread_median_5m_bps = median of spread_bps(bid, ask) over snapshots with
                         sel.avail - 300 <= avail < sel.avail  (fresh at receipt, same contract
                         scale, valid uncrossed two-sided book); needs >= 20 points spanning >= 240 s
  perp_spread_ratio_5m = perp_spread_bps / perp_spread_median_5m_bps  (None if baseline <= 1e-12)
  premium_stress_5m    = |premium_z_5m|
  Derived values are computed from the logged (4-dp rounded) inputs, exactly like the existing
  momentum_gap and vol_shock columns, so every value is reproducible from the CSV. Output rounded
  to 4 dp. Missing inputs give None (never 0, never clipped, never inf/nan).
  Why 300 s: 60 s RV reacts to the very move being measured; 900 s adapts too slowly. A 900 s
  normalised value is NOT added as a column: it equals ret_h / (perp_rv_900s_bps * sqrt(h/60)),
  computable exactly from columns already logged.
  Why this gap denominator: it is the sd of the difference only under independence. Perp and spot
  are strongly positively correlated, so the true sd is smaller and gap_z is CONSERVATIVE. It is
  documented as a volatility-scaled disagreement metric, not a z-score. An empirical gap-RV
  denominator was considered and rejected for now: perp (4 s snapshots) and spot (poll time) are
  sampled asynchronously, so a realized vol of their difference is dominated by asynchronicity
  noise (Epps effect) and would need a new paired series plus its own warm-up.

4. VOLATILITY REGIME (observational; pt.vol_regime)
  s = max of the AVAILABLE ratios among perp_vol_shock_60v300 (REQUIRED), perp_vol_shock_60v900,
      spot_vol_shock_60v300, spot_vol_shock_60v900
  LOW s < 0.5 | NORMAL 0.5 <= s < 1.5 | HIGH 1.5 <= s < 2.5 | EXTREME s >= 2.5 | UNKNOWN (no perp 60v300)
  Constants VOL_REGIME_LOW_BELOW / _HIGH_AT / _EXTREME_AT. Justified by sampling theory only
  (~15 returns per 60 s: relative sd of the 60 s vol estimate ~0.18 in a constant regime, so 1.5 and
  0.5 are ~2.7 sd from 1, 2.5 is ~8 sd). Never tuned against outcomes. Logged, on the dashboard,
  never blocks a call. The continuous ratios remain the analysed quantities.

5. STABILITY STATE (transparent rule; pt.stability_state; no score, no weights)
  component              CAUTION        UNSTABLE
  vol_regime             HIGH           EXTREME
  |momentum_gap_z_60s|   >= 1.0         >= 2.0
  premium_stress_5m      >= 2.5         >= 4.0
  perp_spread_ratio_5m   >= 2.0         >= 4.0
  UNSTABLE: any UNSTABLE component, or >= 2 CAUTION components. CAUTION: exactly one CAUTION.
  STABLE: all four components available and none triggered. UNKNOWN: row not analysis_ready, or
  inputs missing and nothing triggered (with missing inputs CAUTION/UNSTABLE are lower bounds).
  Reasons are logged (e.g. VOL_EXTREME;SPOT_PERP_DISAGREE). Nothing is labelled liquidation-driven.
  Caveat: the |gap_z| thresholds assume nothing about perp/spot correlation. On simulated
  INDEPENDENT walks |gap_z60| >= 1 fires on ~23% of rows; on real (highly correlated) data it should
  fire far less. The quality report shows the real rate. Any revision must be predeclared from that
  distribution, never from outcomes.

13. API / DATA LIMITATIONS
  The repository's documented endpoints (GET /margin/markets, GET /margin/funding_rates/estimate)
  supply bid, ask, last price, settlement mark, reference (index) price, contract size /
  underlying multiplier, status and a funding estimate. No open interest, liquidation flow, trade
  aggressor side or book depth is available, so none is recorded or inferred. Adding one later
  needs a verified source, a new column group, a schema/feature-version bump, quality coverage,
  and the same Step 3 -> promotion chain. The live API was not queried in this change.
  Pre-existing: kalshi_backtest.py uses a Python 3.12+ f-string (PEP 701), so the suite does not
  run on 3.10/3.11 despite the "3.10 - 3.13 intended" note in SETUP/RUNBOOK (not changed here).

14. DELIBERATELY NOT IMPLEMENTED
  * perp_spread_z_5m: Kalshi spreads are tick-quantised, so the trailing sd is often zero or
    unstable; the median-based ratio is robust. (Could be added later as a secondary feature.)
  * Any weighted stability score, any stability-based veto/confidence change, any use of the regime
    in evaluate()/sizing/stops: forbidden until validated through the chain.
  * Empirical perp-minus-spot RV denominator for gap_z (asynchronous sampling, see 3).
  * A 900 s-normalised momentum column (exactly derivable from logged columns).
  * Making more than one new feature PRIMARY, or interactions candidate-eligible (would need a
    Step 4 policy-schema extension, predeclared before looking at data).
  * MACD/RSI/moving averages or any other TA indicator; liquidation/OI inference.
