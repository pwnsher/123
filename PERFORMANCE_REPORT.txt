CHANGES (production files)
1. run_all_tests.py + test_stage9..12 (tests): the master run sets KALSHI_MASTER_TEST_RUN=1 so each
   stage runs exactly once (previously 143 nested stage executions per master run; now 13).
   Standalone test_stage12.py still re-verifies Stages 1-11, each once. Proof: Stage 13 tests 1-2.
2. perp_telemetry.point_at_or_before: direct binary search over the (ts, value) tuples instead of
   building a timestamp list per lookup. Identical index selection. Proof: Stage 13 tests 3-4
   (20,000+ randomised cases incl. empty/one-point/exact/duplicate/irregular).
3. perp_telemetry trailing_zscore / realized_vol_bps: the window start is found by binary search and
   the series is sliced, instead of scanning the whole history with a filter. The slice contains
   exactly the same elements in the same order, so all arithmetic is identical. Causality is
   untouched (inputs are still only data at/before feature_end). Proof: Stage 13 test 5 (10,000
   helper cases + 10,000 end-to-end feature cycles, every Step 2 field exactly equal), tests 6-7.
4. perp_telemetry.TelemetryCSVLogger: the header is validated once per file identity (st_dev,
   st_ino); ordinary appends no longer reopen the file to read the header. A new or replaced file is
   re-validated and a different schema is still renamed aside. Proof: Stage 13 tests 8-9, Stage 7.
5. http_session.py (new) used by kalshi_dashboard._get, KalshiPerpProvider and OutcomeFetcher:
   one pooled requests.Session per thread (never shared). URL, params, timeout, retries and
   response handling are unchanged; cookies are refused so requests remain stateless like
   requests.get. Proof: Stage 13 tests 10-12. (No live network is used by any test.)
6. analyze_perp_shadow._bootstrap: tickers are aggregated once into integer counts / blocked P&L,
   the grouping is released, and each replicate sums aggregates instead of rebuilding a row list.
   Same seed, same rng.choices draws, same arithmetic order -> bit-identical results.
   Proof: Stage 13 tests 20-22 (incl. multi-row tickers).

DEFERRED (not done; behaviour/timing risk outweighed the gain in this pass)
* Coinbase candle cache consolidation: candles() is a strategy input pinned by the Stage 9
  strategy-function hashes; merging it with web_candles() changes that function. candles()
  already has its own 30 s cache (verified: 2 calls within TTL -> 1 fetch).
* Settlement journal in-memory cache: settle_pending() is pinned, and a process-owned cache would
  silently miss external edits to the JSON journals. Journal behaviour is unchanged.
* Active Kalshi market cache: market selection is strategy-adjacent (current_market is pinned);
  deferred as the spec allows.
* Step 3 / Step 5 bootstraps: already cluster-aggregated in their original design (no change needed,
  benchmarks G and I confirm).
* No async rewrite, no parallel coin evaluation, no module restructuring beyond http_session.py.
